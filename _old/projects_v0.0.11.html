PROJECT 01 운영 · 2026 상반기
#하이브리드검색#품질판단루프

미디어 AI Hybrid RAG

언론·미디어 기관의 문서와 표를 검색해 답변에 근거를 붙이는 RAG 서비스입니다.

핵심 설계
  • 질의를 분석해 의도와 표 데이터 여부로 검색 경로를 나눴습니다. 지난 대화의 맥락도 함께 반영합니다.
  • 그래프 검색(전체 주제 → 관련 개체 주변 탐색)과 문서 검색(재랭킹·임계값)을 병행했습니다.
  • 근거가 부족하면 자료를 다시 요청하거나 질의를 다시 쓰는 품질 판단 루프를 두고, 최종 응답은 별도 판정으로 걸렀습니다.
  • 한국어 임베딩 모델을 비교해 인덱스를 설계했습니다.
내 몫 · 운영에서 배운 것
  • 내 몫 — 검색 경로 설계, 재처리 파이프라인, 검증 기준과 변경 범위 판단. 구현과 반복 실험에는 AI를 썼습니다.
  • 문서 수가 늘면서 발생한 재처리 오류와 스키마 검증 작업은 사례집에 따로 적었습니다.
  • 같은 데이터를 다시 처리했을 때 중복이 쌓이는지도 확인했습니다.
한계

고객사의 운영 시스템에서 팀과 함께 진행한 작업입니다. 검색 고도화의 속도 개선치는 측정 로그가 남아 있지 않습니다.

PROJECT 02 구조 · 2026 하반기
#식별자#카탈로그#데이터거버넌스

EDPP 데이터 설계

문서 파싱·변환·저장·검색을 모듈로 조합하는 사내 플랫폼입니다. 공용 모듈을 개발하고, 데이터 변경과 처리 규칙 변경을 구분할 수 있도록 식별자와 카탈로그를 설계했습니다.

구현한 것
  • GraphRAG 증분 인덱싱 — 제목을 정규화해 기존 개체의 ID를 승계하고 새 것만 발급했습니다. 정규화 규칙의 버전이 바뀔 때만 전체 재정합을 강제합니다. ID 재발급 없이 증분 갱신을 테스트로 확인했습니다.
  • 플랫폼 파트 — 모듈 간 스키마와 데이터 라벨링 정리, 조건 분기·저장·검색 공용 모듈, 프론트 연동 API. 쿠버네티스 기반 MSA 위에서 Spark·Hadoop을 씁니다.
  • 스트리밍 PoC — 입력 스키마를 명시하게 하고 변환·저장 단계 검증과 오류 이벤트로 불일치를 드러냈습니다.
설계한 것
  • 운영 재처리에서 덮어쓰기, 부모 필드명 변동, 재실행마다 늘어나는 인덱스가 반복됐습니다. 원인은 한 값에 정체성·실행 실체·표현을 다 시킨 것이었습니다.
  • 정체성을 세 층(논리 id · 내용 해시 · 표현 키)으로 나누고, 관계는 컬럼이 아니라 원장에, 식별자는 버전 있는 함수로, 덮어쓰기라는 연산은 없앴습니다.
  • 모듈마다 다르게 쓰이던 필드의 정의를 카탈로그 파일에 모으고, CI에서 선언을 검사하도록 설계했습니다. 실행 중에는 불일치 여부를 관찰하도록 역할을 나눴습니다.
  • 설계를 네 관점의 독립 검토에 맡겨 36개 지적을 받고 여덟 개 원인으로 분류했습니다. 자체 테스트 전부 통과는 설계가 맞다는 증거가 아니었습니다.
한계

"설계한 것"은 설계 제안과 로컬 프로토타입 단계로 실환경 연동 전입니다. 변환 로직이 바뀌면 함수 버전도 달라져 전체 재처리가 필요합니다.

PROJECT 03 연구 · 2025
#지식그래프#한국어 NLP

지구다

경제 유튜브 대본에서 "금리가 떨어졌다" 같은 구문을 추출해 지식그래프로 연결한 팀 프로젝트입니다.

판단과 시행착오
  • 금리와 환율의 관계를 한 문장으로 정의할 수 없었습니다. 키워드 노드로는 경제 현상이 담기지 않아, 명사와 동사가 붙은 구문을 노드로 삼았습니다.
  • 구문 경계를 자를 모델이 필요했습니다. 여러 한국어 모델을 직접 시도한 끝에 경제 서브토큰을 가진 모델을 골라 일부 레이어와 토큰 분류기를 학습했습니다.
  • 토큰 간 attention을 2차원으로 보고 CNN으로 구문 분리와 관계 추출을 한 번에 하려 했습니다. 성능이 기준에 못 미쳐 구절 끝 태깅으로 확정했습니다.
  • 표현이 다른 구문이 같은 현상인지 판별해야 했습니다. CLS 단독, 인코더 교체, 동의어 사전, 압축 네 가지를 같은 데이터로 비교해 CLS와 토큰 가중 평균을 결합·투영하는 방식으로 결론냈습니다.
내 몫 · 팀
  • 내 몫 — 스크립트 전처리, 구문 분리 모델 선정·학습, 노드 동일성 비교 실험, attention 실험
  • 팀 — 컨셉맵·이벤트 토픽 모델, 관계 추출과 링크 예측(R-VGAE 디코더 교체), Neo4j 적재, 웹·크롬 확장
  • 4인 팀 · 한국경제신문 SW 지능정보 아카데미 6기
한계

교육 과정의 팀 프로젝트입니다. 링크 예측 점수는 발표자료에서 재점검 대상으로 남아 있어 제외했습니다.

PROJECT 04 검증 · 2026.09
#시계열#실험설계

설비 상태 트윈

공개 유압 시험대 데이터로 부품 상태를 판별하고, 센서 오류가 의심되면 판단을 보류하도록 만든 모델입니다.

무엇을 확인했나
  • 원본 데이터에서 잘 구분하던 상태를 센서 하나에 편향을 넣자 잘못 판별했습니다.
  • 여러 온도 센서에 같은 편향을 넣었을 때 평가한 모델이 오판했습니다. 상태별 센서 간 차이의 분포를 학습해 분포를 벗어난 입력은 판단을 보류하도록 바꿨습니다.
  • 센서 오류 조건의 판단 기회 7만 3천여 회에서 오판 0, 판단 발행률 83.8%였습니다. 보류를 정답으로 세지 않고 미검출로 계산했습니다.
검증을 어떻게 설계했나
  • 가설을 코드 실행 전에 파일로 고정했습니다.
  • 기각한 후보를 삭제하지 않고 코드째 보존했습니다. 공통 편향에서 발행한 판단이 전부 틀렸던 후보입니다.
  • 같은 입력이면 같은 산출물이 나오도록 코드·모델·설정을 해시로 고정하고, 단위 테스트와 실제 브라우저 검사를 함께 돌렸습니다.
한계

공개 데이터 1개 시험대입니다. 부품 상태 구분이며 잔여 수명 예측이 아니고, 판단 기회 수는 독립 사례 수가 아닙니다. 요구사항·데이터 계약·평가 기준은 제가 정했고 구현과 실험 실행에는 AI를 썼습니다.
