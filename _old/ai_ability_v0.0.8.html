운영 모니터링 에이전트

회사 업무 · Kubernetes · Read-only

정상처럼 보이는 실패를 사람보다 먼저 알립니다. 회사에서 쿠버네티스로 배포한 서비스를 지켜보는 에이전트입니다.

파이프라인이 행 하나의 오류로 멈추지 않게 설계하자, 실패까지 조용해졌습니다. 로그 규칙만으로는 다 잡히지 않았습니다. 그래서 읽기 전용 계정으로 파드·이벤트·노드 변화를 구독하고, 상태가 바뀔 때만 이상 여부를 판단하는 에이전트를 만들었습니다.

파드가 재시작되면 직전 로그와 종료 사유를 바로 남기고, 같은 사유의 알림은 묶어서 보냅니다. "처리 건수 0"처럼 정상으로 보이는 실패는 규칙으로 정의하기 전까지 에이전트도 놓쳤기에, 못 잡은 오류 종류마다 탐지 방식을 스크립트로 쌓았습니다.

OpenClaw

Self-hosted Multi-Agent · Read / Execute 분리

웹을 보는 에이전트는 실행하지 못하고, 실행하는 에이전트는 바깥이 없습니다. 집에 둔 미니 서버에서 스스로 돌아가는 멀티 에이전트입니다.

에이전트를 자동으로 굴릴 때 가장 현실적인 위험은, 바깥에서 읽어 들인 글에 숨은 명령이 에이전트를 조종하는 것입니다. 그래서 일을 manager · reader · worker · auditor 네 역할로 나누고, 웹 접근과 코드 실행을 같은 에이전트에 주지 않았습니다. 에이전트끼리 직접 주고받는 통로도 없이 모든 흐름은 manager를 거칩니다.

운영해 보니 이 교차 제한이 비대칭이었습니다. 실행 쪽은 망이 없지만 웹 쪽은 HTTPS로 무엇이든 내보낼 수 있었습니다. 나가는 목적지를 허용 목록으로 좁혔고, reader가 읽어온 것은 지시가 아니라 데이터로만 다뤄 worker에는 원문을 넘기지 않고 manager가 다시 쓴 요약만 넘기게 했습니다.

야간에 구현을 맡기면 승인 대기로 멈춥니다. 되돌릴 수 있는 명령은 규칙으로 자동 허용하고, 파괴 가능성이 있는 명령만 감독 에이전트가 대상 상태를 직접 확인해 근거를 기록하며, 판단이 어렵거나 지연되면 기본값은 거부로 두고 사람에게 넘깁니다. 검증하는 auditor는 망이 없는 샌드박스에서 검사를 실행할 수 있지만, 결과물을 고치지는 못합니다.

한번 뚫리더라도 피해가 이 서버 한 대 안에서 멈추도록, 네트워크부터 호스트·계정·컨테이너·에이전트까지 겹겹이 막았습니다.

Paper-Trading Supervisor

Daemon executes · LLM supervises · Human switches

규칙은 코드가, 판단은 LLM이, 실계좌 전환은 사람이 합니다. 모의투자 계좌에서 무인으로 도는 운영 시스템입니다.

상주 데몬이 손절과 비중 한도 같은 기계적 규칙으로만 체결합니다. LLM 감독자는 시장과 투자 원칙을 검토해 설정 파일을 고치고 다음 검토 시각을 스스로 정합니다. LLM은 체결 경로에 없습니다. 설정을 통해 간접적으로 영향을 줄 수는 있어, 실계좌 전환은 사람이 승인합니다.

수익이 나던 전략도 장기 백테스트가 기각하면 내렸습니다. 브로커 인증이 여러 번 끊겼을 때도 감독자는 데몬의 토큰을 건드리지 않았고, 확보하지 못한 숫자는 추정으로 채우지 않고 미확인으로 남겼습니다.

수익률은 쓰지 않습니다. 벤치마크 없는 수익률은 정보가 아니고, 로그에 검증 가능한 값이 없기 때문입니다. 이 시스템이 증명하려는 것은 수익이 아니라, 무인으로 돌아도 정해 둔 경계를 넘지 않는다는 점입니다.
