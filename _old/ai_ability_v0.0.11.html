운영 모니터링 에이전트

서비스의 상태 변화와 처리 오류를 감지해 알립니다. 회사에서 쿠버네티스로 배포한 서비스를 지켜보는 에이전트입니다.

파이프라인이 행 하나의 오류로 멈추지 않게 설계하자, 실패까지 조용해졌습니다. 로그 규칙만으로는 다 잡히지 않았습니다. 그래서 읽기 전용 계정으로 파드·이벤트·노드 변화를 구독하고, 상태가 바뀔 때만 이상 여부를 판단하는 에이전트를 만들었습니다.
  1. 01
    구독파드 · 이벤트 · 노드
  2. 02
    판단상태가 바뀔 때만
  3. 03
    기록직전 로그 · 종료 사유
  4. 04
    알림같은 사유는 묶어서

에이전트는 읽기 전용으로 상태를 확인하고 알림을 보냅니다. 서비스 변경은 사람이 처리합니다.

적용 범위
회사 내부 서비스라 화면과 설정은 공개하지 않습니다. 탐지 규칙은 놓친 사례가 생길 때마다 더하는 방식이라, 아직 정의하지 않은 실패는 잡지 못합니다.
Kubernetes읽기 전용 계정상태 전이 판단
운영하며 바꾼 것

파드가 재시작되면 직전 로그와 종료 사유를 바로 남기고, 같은 사유의 알림은 묶어서 보냅니다. "처리 건수 0"처럼 정상으로 보이는 실패는 규칙으로 정의하기 전까지 에이전트도 놓쳤기에, 못 잡은 오류 종류마다 탐지 방식을 스크립트로 쌓았습니다.

개인 서버 · 운영 중

OpenClaw

웹 자료를 읽는 역할과 코드를 실행하는 역할의 권한을 분리했습니다. 집에 둔 미니 서버에서 스스로 돌아가는 멀티 에이전트입니다.

웹 문서에 포함된 명령이 코드 실행으로 이어질 수 있어 접근 권한을 나눴습니다. 그래서 일을 manager · reader · worker · auditor 네 역할로 나누고, 웹 접근과 코드 실행을 같은 에이전트에 주지 않았습니다. 에이전트끼리 직접 주고받는 통로도 없이 모든 흐름은 manager를 거칩니다.
역할웹 접근코드 실행
manager조율자허용차단
모든 흐름이 거쳐 감
reader자료 수집자허용차단
읽은 내용은 지시가 아닌 데이터로만 다룸
worker실행자차단허용
망 없음 · manager가 다시 쓴 요약만 받음
auditor검증자차단허용
망 없는 샌드박스 · 결과물 수정 불가

어느 역할도 웹 접근과 코드 실행을 함께 갖지 않고, 역할끼리 직접 이어지지 않습니다.

적용 범위
개인 서버에서 개인 용도로 운영합니다. 승인 체계는 일회용 컨테이너에 한정해 적용했고, 설계 매뉴얼은 실환경 값을 마스킹한 공개본입니다.
읽기·실행 분리Multi-AgentRootless Docker
운영하며 바꾼 것

운영해 보니 이 교차 제한이 비대칭이었습니다. 실행 쪽은 망이 없지만 웹 쪽은 HTTPS로 무엇이든 내보낼 수 있었습니다. 나가는 목적지를 허용 목록으로 좁혔고, reader가 읽어온 것은 지시가 아니라 데이터로만 다뤄 worker에는 원문을 넘기지 않고 manager가 다시 쓴 요약만 넘기게 했습니다.

야간에 구현을 맡기면 승인 대기로 멈춥니다. 되돌릴 수 있는 명령은 규칙으로 자동 허용하고, 파괴 가능성이 있는 명령만 감독 에이전트가 대상 상태를 직접 확인해 근거를 기록하며, 판단이 어렵거나 지연되면 기본값은 거부로 두고 사람에게 넘깁니다. 검증하는 auditor는 망이 없는 샌드박스에서 검사를 실행할 수 있지만, 결과물을 고치지는 못합니다.

오류나 잘못된 명령의 영향을 줄이기 위해 네트워크 접근과 실행 권한을 제한하고, 계정·컨테이너를 분리했습니다.

개인 서버 · 모의투자 계좌

모의투자 감독

코드가 주문을 실행하고 LLM이 전략 설정을 검토합니다. 모의투자 계좌에서 무인으로 도는 운영 시스템입니다.

  • 데몬
    손절·비중 한도 같은 규칙으로 주문을 실행합니다. 주문 권한은 데몬에만 있습니다.
  • LLM 감독자
    시장과 투자 원칙을 검토해 설정을 고칩니다. 바뀐 설정은 데몬의 이후 주문에 반영됩니다.
  • 백테스트
    장기 백테스트가 기각한 전략은 수익이 나던 것이라도 내립니다.
  • 사람
    실계좌로 바꾸는 작업을 승인합니다.
적용 범위
모의투자 계좌입니다. 코드는 이 포트폴리오 저장소에 없고, 실행 로그와 운영 기록으로 남아 있습니다.

수익이 나던 전략도 장기 백테스트가 기각하면 내렸습니다. 브로커 인증이 여러 번 끊겼을 때도 감독자는 데몬의 토큰을 건드리지 않았고, 확보하지 못한 숫자는 추정으로 채우지 않고 미확인으로 남겼습니다.

모의투자 환경에서 주문 실행과 전략 검토의 역할을 나누고, 인증 오류나 확인하지 못한 데이터가 생겼을 때의 처리를 점검했습니다. 검증 가능한 수익률 기록은 남아 있지 않습니다.
